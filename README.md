## How It Works

```
Child holds BOOT button
    │
    ▼
ESP32-S3 records voice via INMP441 I2S mic
(32-bit stereo Philips mode, left channel extracted to 16-bit mono)
    │
    ▼
Pitch shift applied on-device (OLA algorithm, PITCH_FACTOR 1.35)
Real voice never leaves the hardware — only shifted robot voice is sent
    │
    ▼
WAV uploaded to Groq Whisper (STT) via HTTPS multipart POST
Returns transcribed text in the child's language
    │
    ▼
Text sent to Groq LLaMA 3.1-8b-instant (AI) via HTTPS POST
System prompt: Sparkle the fairy — 2-3 short sentences, fun, never scary
History kept for last 6 turns (MAX_HISTORY) for conversational memory
    │
    ▼
AI reply sent to VoiceRSS (TTS) via HTTPS GET
Returns 16kHz 16-bit mono WAV
    │
    ▼
Dual-core streaming playback:
  Producer task (Core 0): downloads WAV → parses RIFF header → fills 96KB ring buffer in PSRAM
  Consumer task (main):   reads ring buffer → pads 16-bit PCM to 32-bit → I2S DMA → MAX98357A → speaker
Playback starts after 24KB prebuffer (~0.75s) to prevent starvation
    │
    ▼
OLED shows emotion face for 700ms based on reply keywords
Then switches to SPEAKING face while audio plays
RGB LED mirrors face state throughout
    │
    ▼
Returns to IDLE face + RGB breathing animation
```

## Wiring

### CH9102 Driver — Install Before Anything Else

Board uses CH9102 USB chip. Download driver from **wch.cn**, install, reboot PC, plug in via USB-C. A COM port must appear in Device Manager before any upload.

### Solder Pin Headers

Board ships unsoldered. Tack one corner pin per row to hold straight, then solder the rest.

### INMP441 Microphone → ESP32-S3

| INMP441 | ESP32-S3 GPIO | Notes |
|---------|--------------|-------|
| VDD | 3.3V | Must be 3.3V — not 5V |
| GND | GND | |
| SCK | GPIO 14 | I2S bit clock |
| WS | GPIO 15 | Word select |
| SD | GPIO 16 | Serial data out |
| L/R | GND | Left channel selection |

### MAX98357A Speaker Amp → ESP32-S3

| MAX98357A | ESP32-S3 GPIO | Notes |
|----------|--------------|-------|
| VIN | 3.3V | Connect to 3.3V — the VBUS 5V pin on S3 is input only, not output |
| GND | GND | |
| BCLK | GPIO 12 | I2S bit clock |
| LRC | GPIO 13 | Left/right clock |
| DIN | GPIO 11 | Serial data in |
| SD | 3.3V | Must be HIGH to enable amp — floating = random mute |
| GAIN | GND | Tie to GND for 9dB gain |

### SSD1306 OLED → ESP32-S3 (I2C)

| OLED | ESP32-S3 GPIO | Notes |
|------|--------------|-------|
| VCC | 3.3V | |
| GND | GND | |
| SCL | GPIO 9 | I2C clock |
| SDA | GPIO 8 | I2C data |

### Indicator LED

| Component | ESP32-S3 GPIO | Notes |
|-----------|--------------|-------|
| LED anode (+) | GPIO 4 | Via 330Ω resistor to GND |

**GPIO 0** = BOOT button (already on board, used as talk button)  
**GPIO 48** = RGB NeoPixel (already on board, no wiring needed)  
**Do not use GPIO 1** — it is the TX pin, conflicts with Serial

## Software Architecture

### Files

```
firmware/
├── firmware.ino      Main sketch — all logic lives here
├── faces.h           OLED face library — 12 animated expressions
├── Sparkle_RGB.h     RGB NeoPixel library — 13 mood modes
├── ota.h             OTA updater — checks GitHub on every boot
└── secrets.h         Your keys — generated by CI, never committed
```

### firmware.ino — Function Map

| Function | What it does |
|----------|-------------|
| `urlEncode()` | Percent-encodes text for VoiceRSS URL — handles Unicode, Hindi, punctuation |
| `setupMic()` | Configures I2S0 — Philips 32-bit stereo (required for INMP441 on ESP32-S3) |
| `setupSpeaker()` | Configures I2S1 — MSB 32-bit mono (required for correct DMA clock on S3) |
| `makeWavHeader()` | Builds a 44-byte RIFF WAV header for the recorded audio |
| `pitchShift()` | Overlap-add pitch shift — raises voice by 1.35× before sending to cloud |
| `recordWhileHeld()` | Records I2S audio in 128-frame chunks while button is held, stops on release |
| `writeSpeaker()` | Pads 16-bit PCM samples to 32-bit left-justified for I2S DMA, plays in 256-sample chunks |
| `ensureWiFi()` | Reconnects WiFi if dropped — called before every API request |
| `printNetworkState()` | Prints heap, PSRAM, WiFi RSSI to Serial for debugging |
| `transcribe()` | Posts WAV to Groq Whisper via multipart form-data, returns text |
| `askAI()` | Posts conversation history to Groq LLaMA, sanitizes reply for JSON safety |
| `speakText()` | Dual-core streaming TTS — producer fills ring buffer, consumer plays it |
| `pickFaceState()` | Maps keywords in AI reply to a FaceState enum |
| `setFaceAndRGB()` | Sets both OLED face and RGB LED to the same state atomically |
| `showFaceAndRGBFor()` | Holds a face+RGB state for a fixed duration with tick() loop |
| `connectWifi()` | Connects WiFi on boot, shows IP on OLED |
| `setup()` | Allocates PSRAM buffers, inits hardware, connects WiFi, runs OTA check |
| `loop()` | Button detection → record → pitch shift → STT → AI → emotion face → TTS → idle |

### faces.h — Face Library

12 animated expressions rendered at ~12fps on the SSD1306 128×64 OLED.

Uses pixel-art primitives: `eye()`, `pupil()`, `brow()`, `smileCurve()`, `frownCurve()`, `heart()`, `sparkle()`, `blush()`, `sadFrown()`, `happyCurve()`, `cuteClosedEye()`, `cuteSpeechMouth()`.

Public API:
- `Face::begin()` — init I2C and OLED
- `Face::setState(FaceState)` — change expression, resets frame counter
- `Face::tick()` — call every loop, renders at 12fps
- `Face::showStateFor(state, ms)` — hold a face for fixed duration

### Sparkle_RGB.h — RGB Library

Controls the built-in NeoPixel on GPIO 48. 13 mood modes each with unique animation.

Public API:
- `RGB::begin()` — init NeoPixel
- `RGB::setMode(Mode)` — change mode
- `RGB::tick()` — call every loop for animation
- `RGB::off()` — turn off LED

RGB::tick() is deliberately NOT called during mic recording, STT, AI, or TTS audio paths to prevent I2S interference.

### ota.h — OTA Updater

On every boot after WiFi connects:
1. Fetches `version.txt` from `raw.githubusercontent.com/shenoiz/princess_ai_bot/main/version.txt`
2. Compares with `FW_VERSION` compiled into the firmware
3. If different — fetches latest release `.bin` URL from GitHub Releases API
4. Downloads and flashes via `httpUpdate.update()`
5. Device reboots into new firmware automatically

## First USB Flash

This is the only time USB is needed.

1. Copy `firmware/secrets.h.example` → `firmware/secrets.h`
2. Fill in all five values — WIFI_SSID, WIFI_PASS, GROQ_KEY, HF_TOKEN, VOICERSS_KEY
3. Open `firmware/firmware.ino` in Arduino IDE — all tabs load automatically
4. Set board settings from the table above
5. Click Upload
6. Open Serial Monitor at 115200 baud — you should see WiFi OK, OTA check, then Ready

After this — every update goes over Wi-Fi automatically.

## Branch Strategy

This project uses **Gitflow**. Direct pushes to `main` and `develop` are blocked by branch protection rules.

```
main        ← production. CI fires only here. Merged PRs only.
develop     ← integration. All features merge here first.
feature/*   ← your working branch. Always branch from develop.
hotfix/*    ← urgent fix. Branch from main directly.
```

### Day-to-day flow

```bash
# 1. Start from develop
git checkout develop
git pull origin develop

# 2. Create feature branch
git checkout -b feature/my-change

# 3. Make changes and commit
git add .
git commit -m "feat: describe your change"
git push origin feature/my-change

# 4. Open PR on GitHub: feature/my-change → develop
# 5. Review and merge

# 6. When ready to release: open PR: develop → main
# 7. Merge → CI pipeline fires → device updates on next boot
```

### Branch protection rules to set

Repo → Settings → Branches → Add rule:

**For `main`:**
- Require pull request before merging
- Require 1 approval
- Block direct pushes

**For `develop`:**
- Require pull request before merging
- Block direct pushes

## CI/CD Pipeline

Pipeline file: `.github/workflows/build.yml`

Fires automatically when a PR is merged into `main`. Watch it live under the **Actions** tab.

| Step | What happens |
|------|-------------|
| 1 | Checkout full git history |
| 2 | Install arduino-cli |
| 3 | Install ESP32-S3 core (Espressif 3.0.7) |
| 4 | Install Adafruit SSD1306, GFX, NeoPixel, ArduinoJson |
| 5 | Generate secrets.h from GitHub Secrets — keys never in repo |

## OTA Updates

After merging a PR to main and CI completing:

1. Press RST on the board (or power cycle)
2. Board connects to WiFi
3. Fetches `version.txt` from GitHub
4. Compares with `FW_VERSION` in flash
5. If different: downloads `.bin` from GitHub Releases, flashes, reboots
6. Serial Monitor shows new version number on boot

OTA uses the `Huge APP` partition scheme which reserves space for the update. Never change the partition scheme or OTA will fail.

## RGB LED Modes

Built-in NeoPixel on GPIO 48 mirrors the OLED face state. Each mode has a unique colour and animation pattern.

| Mode | Colour | Animation |
|------|--------|-----------|
| IDLE | Soft blue | Slow breathing |
| LISTENING | Cyan | Static — frozen during mic capture |
| THINKING | Purple shifting | Breathing with hue drift |
| SPEAKING | Blue-white | Static — frozen during I2S audio |
| HAPPY | Warm amber | Breathing |
| LOVE | Deep pink | Double heartbeat pulse |
| EXCITED | Rainbow | Fast colour wheel + breathing |
| SURPRISED | White flash | Decay pulse then settle |
| SAD | Deep blue | Slow breathing |
| SLEEPY | Dark blue-grey | Very slow breathing |
| WINK | Hot pink | Breathing |
| CURIOUS | Sky blue | Breathing |
| OTA | Blue-cyan | Breathing during update |

RGB::tick() is intentionally not called during microphone recording or I2S audio playback to prevent interference with audio hardware.

## Privacy — Robot Voice

The child's real voice **never leaves the device**.

Before any audio is sent to the internet, the ESP32-S3 runs a pitch-shift algorithm (overlap-add, PITCH_FACTOR 1.35) that raises the voice by 35%. The result sounds robotic. Groq Whisper transcribes it accurately. Only the shifted audio and text travel online.

## Troubleshooting

**Board not showing as COM port**  
Install CH9102 driver from wch.cn and reboot PC.

**PSRAM alloc failed in Serial Monitor**  
Tools → PSRAM → OPI PSRAM. Must be set exactly.

**OTA not updating**  
Check GH_USER and GH_REPO in ota.h match your GitHub username and repo name exactly. Both are case-sensitive.

**No sound from speaker**  
Check MAX98357A SD pin is connected to 3.3V — floating SD pin causes random mute. Check VIN is on 3.3V not 5V (ESP32-S3 VBUS is input only).

**Mic only catching one word**  
Hold button and speak immediately — recording starts the instant button is pressed. Do not pause before speaking.

**400 error on AI after first query**  
Special characters in AI reply breaking JSON history. The sanitize block in askAI() handles this — check it is present in your firmware.

**CI pipeline not showing in Actions tab**  
Pipeline only fires on push to main. You must merge a PR into main — direct pushes are blocked by branch protection.

**TTS stutter between sentences**  
VoiceRSS free tier has variable delivery speed. Reduce MAX_TOKENS to shorten replies and reduce audio duration. Current setting is 120 — try 60 or 80.
